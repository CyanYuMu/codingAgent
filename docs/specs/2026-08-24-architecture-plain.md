# codeclaw 架构白话版

> 配套文档：[架构总结（术语版）](2026-08-24-architecture-overview.md)
> 这份文档不用术语，只回答两个问题：**这一块是干嘛的**、**它是怎么做到的**。

---

## 先看整体：这个程序到底在干什么

你打一句"帮我改个 bug"，它就开始来回转圈：

**想一步 → 动手做一件事 → 把结果记下来 → 再想一步 → ……** 直到它觉得不用再动手了。

就这么简单。剩下所有的复杂度，都是在解决这个圈转起来之后会遇到的四个麻烦：

1. 转着转着，**材料太多，模型看不下了**（→ 上下文治理）
2. 转着转着，**上次聊过的事忘光了**（→ 记忆）
3. 一个人转太慢，**想找几个帮手同时干**（→ 子 agent）
4. 它可能**删你的文件**（→ 权限）

下面一块一块说。

---

## 1. 那个圈：Agent 循环

**干嘛的**：驱动"想一步、做一件事"。

**怎么做的**：一个 `for` 循环，每转一圈干五件事——

1. 看看有没有人中途塞纸条给它（比如你按 Ctrl+E 补一句话）
2. 材料快满了就先压缩一下
3. **把档案袋里的所有材料重新拿出来**，交给模型
4. 模型回一段话，可能带着"我要用 read_file 这个工具"
5. 把工具跑了，结果写进档案袋，进入下一圈

模型这次没说要用工具？那这一轮就结束了，等你下一句话。

**一个容易忽略但很关键的点**：第 3 步是"重新拿"，不是"在内存里存一份列表往后加"。因为中途可能有人塞纸条、可能刚压缩过材料，内存里的副本随时会过期。所以宁可每次重新拿。

---

## 2. 档案袋：Session

**干嘛的**：把整个对话记下来，用来重新装填模型的输入，也用来事后审计。

**怎么做的**：一个**只能往后追加、永不修改**的记事本文件（一行一件事）。

- 要"回到某个点重来"？不删东西，只写一行"从这里开始新的一支"，然后顺着指针往回读。
- 你按 Ctrl+C 打断了，记事本里可能留下"我要调 bash"但没有结果。下次接着聊的时候，模型 API 会因为"有调用没结果"直接报错。所以读记事本的时候会**自动补一行"这个工具没跑成"**，只在内存里补，不写回文件。

---

## 3. 材料太多：上下文治理

**干嘛的**：模型一次能看的字数有上限（比如 12.8 万 token），快满了得处理。

**怎么做的**：三招，从便宜到贵。

**第一招：长输出不进对话，只留链接。**
比如你让它跑一个测试，输出 5 万字。那对话里只留开头 4000 字节 + 结尾 4000 字节，中间写一句"省略了 xx 字节"，再附一个 `artifact://3`。完整内容存在磁盘上。模型想看细节，用 `read_file` 打开这个链接按行读就行。

**第二招：老材料换成摘要。**
什么时候换？模型每次回话都会告诉你"这次读了多少字"，超线就换。而且**是在下一次问模型之前就换掉**，不是等这一轮全干完——不然一轮里连着调 20 次工具，中途就撑爆了。

**从哪里切？** 这里有个坑：不能把"我要调工具"和"工具的结果"劈开，劈开了 API 直接报错。所以先按字数倒着数出一个大概位置，然后**往前退**，一直退到"某句用户说的话"或者"某段没带工具调用的回复"为止。

**摘要写什么？** 不是聊天总结，是写给接班人的交接单，固定六段：
目标是什么 / 现在做到哪了 / 定了哪些事 / 碰过哪些文件 / 哪些路走不通 / 下一步干嘛。

**第三招：实在放不下就砍狠一点。**
如果模型直接报"超长了"，就把"保留最近多少"这个数砍一半再压一次；还是不行就只留最后一段。

---

## 4. 长期便签：记忆

**干嘛的**：档案袋只管这一次对话。你上周说过"这个项目不要用 tab 缩进"，换个对话就没了——记忆管这个。

**怎么做的**：

- 一个 SQLite 数据库 + 全文搜索。
- 模型觉得某句话重要（你的偏好、关键决策），就调 `remember` 工具存一条。
- 每次问模型之前，拿你最后说的那句话去搜，挑 5 条最相关的，贴在系统提示后面，并标注"这只是背景，当前的对话更重要"。
- 怎么挑？**纯代码算分，不用模型判断**：文字匹配度 × 0.5 + 重要性 × 0.3 + 新鲜度 × 0.2，再乘一个可信度。新鲜度是 72 小时衰减一半。

**目前这块有两个毛病，值得知道**：

1. 搜索词是把你的原话**直接扔给数据库**的。你要是问"这个函数怎么处理 (a, b)？"，括号和问号会让数据库语法报错——**而这个错误被代码吞掉了**，表现就是"什么都没搜到"，你完全看不出来出过错。
2. 每一步都重新搜一次。这会让发给模型的开头部分每轮都变，模型那边的缓存一直命中不了，纯亏钱。

---

## 5. 一个项目一个抽屉：多会话管理

**干嘛的**：你在 A 项目聊的东西，不该跑到 B 项目去。

**怎么做的**：按你启动时所在的目录，把数据分到不同抽屉：

```
~/.codeclaw/projects/<目录名编码后>/
    ├── memory.db          这个项目的记忆
    ├── current            当前是哪个会话
    ├── 20260824-101500_8f2c1d.jsonl     一次对话的记事本
    └── 20260824-101500_8f2c1d/          这次对话产生的文件
          ├── 0.bash.log                 → artifact://0
          ├── Reviewer.md                → agent://Reviewer
          └── agent-Reviewer-3f9a1c.jsonl → history://Reviewer
```

目录名编码之前会先解开软链接，所以同一个目录的不同写法会落到同一个抽屉。

配置分三层读，后面的盖前面的：全局的 → 项目里的 `.codeclaw/config.yaml` → 仓库根的老配置。

---

## 6. 别把我文件删了：工具与权限

**干嘛的**：模型要跑命令、写文件，得有个闸。

**怎么做的**：

- 每个工具自己声明危险等级：**读**（read_file、grep）/ **写**（write_file）/ **执行**（bash）。
- 你设一个模式：**全都问** / **只问执行**（默认）/ **全放行**（`--yolo`）。
- 两者一交叉就得出"放行 / 问一下 / 拒绝"。这是个纯函数，没有任何副作用，所以特别好测。
- 谁来问？有界面就弹窗；`-p` 这种没界面的模式**直接拒绝**，并告诉模型"我拒绝是因为没法弹窗，你让用户加 --yolo"。

**并发**：能同时跑的（读文件、搜索）就同时跑；会打架的（bash、写文件）排队一个一个来。

---

## 7. 找帮手：子 agent（重头戏）

用**外包**来理解最容易。

### 为什么要外包

主 agent 的"脑容量"有限。让它自己读 30 个文件，读完脑子就满了。不如派个人去读，**只把结论带回来**。

### 派之前：先查作业

模型想派活，得填一张单子：

- **整批共享的背景**：目标是什么、不能碰什么、几个人之间怎么对接口。必填。
- **每一项任务**：改哪些文件、怎么改、怎么算做完。

**任务描述少于 40 个字直接打回**，不启动任何人。理由很实在：外包的人**看不到你和用户的聊天记录**，你只给一句话，他只能靠猜。

其它检查：这个 agent 存不存在、允不允许他再往下转包、转包深度到没到头（默认最多两层）、名字有没有重。**任何一项不过，整批都不派**——半个批次跑起来更难收拾。

### 派出去之后：每个人的装备

| 每人一份 | 为什么 |
|---|---|
| 自己的记事本 | 事后能查他到底干了什么 |
| 自己的终端 | 他 `cd` 到别处不会影响其他人。以前是共用一个，一个人切目录全员遭殃 |
| 裁剪过的工具箱 | reviewer 只给读文件的工具，他想改代码也改不了 |
| 和你一样的审批规则 | **派活不等于放行**。以前是子 agent 一律 yolo，等于所有需要审批的操作，转包出去就免审了 |

### 怎么并行

一个号码牌池子，默认 4 张。拿到牌才能开工，干完还牌，没牌的排队。这个池子还能**中途改大小**：调小的时候，如果牌都在别人手里，就记一笔"账"，等他们还牌的时候直接扣掉——**不打断正在干活的人**。

### 怎么交作业

**必须调 `yield` 这个工具交。** 只在自己的输出里写字不算，那些字不会回到主 agent。

`yield` 有三种用法：

- `yield(data=...)` —— 交最终结果，交完立刻收工
- `yield(data=..., section="findings")` —— 先交一段，还能接着干
- `yield(error="我卡在 xxx")` —— 干不了，说明卡在哪，也算收工

### 交得不对怎么办

如果这个角色规定了产出格式（比如 reviewer 必须交 `{findings: [...], verdict: "..."}`），就拿一个简易校验器比对：

- 不合格 → **把具体哪儿不对、还剩几次机会告诉他，让他重交**，最多 3 次
- 第 4 次还不对 → 宽松模式就收下但打个警告；严格模式直接判失败

### 一直不交怎么办

三级提醒：

1. 第 1、2 次："你还没交作业，只写文字是没用的"
2. **第 3 次：直接把他的工具箱清空，只剩 `yield`**——他除了交作业什么都干不了

三次之后还是没交：如果这个角色本来就要求格式化产出，判失败；如果本来就是探索类的没格式要求，那就收下他最后那段文字，但标明"这是最后的输出，不一定是完整结论"。

### 花太多钱怎么办

给每个人一个"最多问模型多少次"的软预算（默认 200 次，只读角色 100 次）：

- **到 200 次**：塞一张纸条"该收尾了，到 300 次会强制停"
- **到 300 次（1.5 倍）**：**掐断当前这一轮**（但人还活着），下一轮只剩 `yield`，逼他交
- **再熬 5 次还不交**：直接杀掉

### 出事了怎么办

状态如实记：超时就是 `timeout`，被杀就是 `killed`，你按 Esc 就是 `aborted`。**绝不把半成品报成成功**——以前会，导致主 agent 拿着半成品当结论往下做。

所有结束的人都进"待命"状态：记事本和产出文件都留着，你随时能把他**叫回来接着干**（`/agent Reviewer 再核对一下 X`）。叫回来的时候预算和提醒次数会重新算，不然上次用满的预算会让他一回来就被强制收尾。

---

## 8. 长任务不卡住你：后台作业

**干嘛的**：派了三个人去干 10 分钟的活，主 agent 不该干等着。

**怎么做的**：

- 派活的时候写 `background: true` → 工具**立刻返回三个工单号**，主 agent 接着跟你聊。
- 有人干完了 → 结果自动塞进主 agent 的下一轮，前面加一句"后台作业 X 完成了，用这个结果继续"。
- 主 agent 正在忙？当纸条塞给它下一步。主 agent 闲着？自动起一轮让它处理。

**一个很关键的实现细节**：后台任务挂在"公司"身上，不挂在"这次派活"这个动作上。不然你按一下 Esc 停掉当前这一轮，后台的活儿会被连带取消，"后台"就是假的。

**结果只送一次**：有三个地方都能取到结果（界面自动取、模型主动查作业、模型等消息），谁先取到谁负责送，取走就没了，不会重复送两遍。

---

## 9. 帮手之间说话：hub

**干嘛的**：A 定了个函数签名，B 得按同一个签名去实现。他俩得能对一句。

**怎么做的**：一个内部聊天工具，六个操作：

- `list` —— 看看现在都有谁、在干嘛
- `send` —— 给某人发一句话
- `inbox` —— 收信
- `wait` —— 实在没事干了，等一会儿（默认 30 秒，最多 120 秒）
- `jobs` —— 看后台作业进度
- `cancel` —— 取消某个作业

**发消息的三种情况**：对方正在干活 → 直接插到他下一步能看到的地方；对方在发呆 → 同上，顺便叫醒他；**对方已经收工了 → 把他叫回来接着干**。

**明文规定：hub 只能传一句话级别的协调，不许传文件内容。** 要给内容就给路径，或者给 `agent://Reviewer` 这种链接。

发出去的每一句话都会记进对方的记事本，写成 `[hub from Explorer] ...`，所以事后能查是谁说的。

---

## 10. 看得见：Agent Hub 面板

按 `ctrl+a` 打开一个面板，能看到每个帮手现在在跑什么工具、问了模型几次、烧了多少 token、什么状态。

**怎么做的**：帮手往一个"广播站"发状态，界面收到就重画。广播站**满了就丢**——因为面板每次重画都是直接去读最新的花名册，丢一条最多晚一帧，不会显示错。真正的真相永远是磁盘上的记事本，广播站只服务于"好看"。

---

## 11. 怎么知道它没写错：评测与审计

- **审计**：记事本本身就是审计日志。统计"这次对话花了多少 token、调了几次工具"，直接从记事本算。
- **评测**：给一道题 + 起始文件 + 标准答案文件，跑完**逐字节比对**。坚持不用另一个模型当裁判。
- **最有用的那部分**：用**假模型**（写死剧本，不联网）来测 harness 自己。比如写一个"永远不交作业"的假模型，然后断言：恰好提醒 3 次、第 3 次它的工具箱里只有 yield、最后判定正确。压缩、权限、状态机都是这么测的——不花一分钱，跑一次几秒钟。

---

## 12. 串起来看一遍

你打一句"帮我把这三个模块的错误处理统一一下"：

1. 主 agent 从**记事本**里拿出全部材料，加上**系统提示 + 环境信息 + 搜出来的 5 条记忆**，问模型。
2. 模型说："这活儿得分三块，我派三个人。" 调 `task`，填好共享背景和三项任务。
3. **查作业**：三项描述都够详细，agent 都存在，深度没超 → 通过。
4. 三个人各拿一张号码牌，同时开工。每人一个记事本、一个终端、一套裁剪过的工具。
5. 面板上能看到他们在跑什么。A 发现了个公共的错误类型，用 `hub` 告诉 B 和 C。
6. A 调 `yield` 交作业 → 格式对 → 收工，完整产出写进磁盘。
7. 三个人的结果回到主 agent，但只是**摘要 + 两个链接**，不是他们的全部聊天记录。
8. 主 agent 觉得需要验收 → 再派一个 `reviewer`（只读、格式严格）去核对。
9. 材料快满了？在下一次问模型之前，把老的换成六段式摘要。
10. 主 agent 综合完给你答复。

---

## 13. 现在有哪些地方是"看着能用其实没在工作"

1. **记忆搜索遇到标点会静默失败**。你问带问号或括号的问题，大概率一条记忆都搜不到，而且没有任何提示——因为错误被吞掉了。
2. **每一步都重新搜记忆**，导致发给模型的开头一直在变，缓存永远命中不了。应该只在第一轮和每次压缩后刷新。
3. **后台作业那套（hub、叫回来接着干）已经写完、测试也全绿，但还没提交**。放久了后面的改动会分不清是谁引入的。

另外这些是设计里写了但还没做的（不是 bug，是排期）：跨会话的"项目地图"（这样新会话不用从零读一遍文件）、只改一段的 `edit` 工具（现在只有整文件覆盖）、bash 危险命令识别、以及按"上周哪个项目花了多少钱"这种维度出报表。
